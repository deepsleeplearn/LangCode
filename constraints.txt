# mlx-audio-plus is a published fork (github.com/DePasqualeOrg/mlx-audio-plus,
# MIT) that installs INTO the `mlx_audio` package namespace. It is the only
# source of the modules our TTS needs - no mlx-audio release from 0.4.3 through
# 0.5.3 ships any of them:
#   mlx_audio/tts/models/cosyvoice3    <- the Fun-CosyVoice3 model itself
#   mlx_audio/tts/models/cosyvoice2
#   mlx_audio/codec/models/s3gen       <- imported by voice/mlx_cosyvoice3.py
#   mlx_audio/codec/models/s3tokenizer <- imported by voice/mlx_cosyvoice3.py
# mlx_audio.tts.utils resolves a model by importing
# `mlx_audio.tts.models.<model_type>` and offers no registry hook, so the module
# has to exist on disk. Without this package the server logs
# "Model type cosyvoice3 not supported for tts" and custom-voice TTS is dead.
#
# It declares transformers<5.0.0,>=4.49.0, which our pinned 4.57.6 satisfies.
# It is still installed --no-deps because it also declares mlx-lm<0.30.0 (we run
# 0.31.3, which works) and pulls mlx-audio[all] plus a large demo tail.
#
# ORDER MATTERS: it overwrites 250 files that mlx-audio 0.4.3 also owns, so it
# must be installed AFTER mlx-audio. start_macos.sh does that in its own pip
# step, which is why this package is not in requirements-voice-nodeps.txt.
mlx-audio-plus==0.1.8

# Not pinned, and not installed: gradio / gradio_client / flask / sox / pytz /

#
# accelerate is the exception and IS installed (pinned above): Qwen3ASRModel
